# CBC + WMTO 통합 설계 (초안)

> 결정 기록과 설계안입니다. 구현 전에 "6. 아직 정할 것"을 확정하세요.

## 0. 한 줄 요약
**CBC**(크리스천 사업가 네트워크, 가칭)를 앞문으로, **WMTO**(선교 층)를 "선교 권한"을 받은 회원에게만 열리는 구조로 한 플랫폼 위에 만든다. 새로 짓지 않고 지금 코드·DB를 확장한다.

## 1. 확정된 결정
| # | 결정 |
|---|---|
| 1 | **한 챕터에 같은 업종은 한 명** (BNI 방식의 업종 독점) |
| 2 | **챕터 규모 30~50명** (기존 "12명 초과 시 분할" 규칙은 폐기) |
| 3 | **선교 권한은 "본인 신청 → 승인"**, 또는 **챕터 리더·운영진이 직접 지정** |
| 4 | **BNI 상표·용어·문구는 쓰지 않고, 법적으로 안전하게** (7장 체크리스트) |
| 5 | 조직·도메인 구조는 8장 선택지 검토 |

## 2. 구조
```
CBC (사업가 누구나 가입)
 ├─ 챕터: 지역별, 업종 독점, 30~50명
 ├─ 정기 모임·출석, 방문자 초대, 1:1 미팅, 리퍼럴, 감사
 └─ 선교 권한(mission_access) 승인된 회원에게만 ↓
     WMTO 층: 선교사 모시기·멘토링, 자립 리포트, 순환 기금, 후원, 캠프
선교사·후원자: WMTO 쪽 사용자(챕터에 들어오지 않음, 지금과 동일)
```
- 앱 이름: **CBC Connect**. WMTO 메뉴 묶음은 권한이 있는 사람에게만 보임.
- 홈페이지: `/`는 CBC, 지금의 WMTO 사이트는 `/wmto/...`로 이동(기존 주소는 308 리디렉션).

## 3. 데이터 모델 변경
기존 표를 최대한 재사용한다(새 데이터베이스 불필요).

**회원/권한**
- `members.mission_status` : `none | requested | approved | revoked` (+ `mission_decided_by`, `mission_decided_at`)
- `mission_requests(id, member_id, message, status, decided_by, decided_at, created_at)` — 신청과 승인 이력
- `chapter_leaders(chapter_id, member_id, title)` — 회장·부회장·멤버십·교육 등 직책. 리더는 **자기 챕터** 회원의 신청만 승인·지정 가능, 운영진(`admins`)은 전체.
- 역할(`role`)은 **그대로 `mentor`를 사업가 회원으로 유지**(이름 변경 비용·위험이 큼). 화면 문구만 "사업가 회원"으로 바꾸고, WMTO 기능(매칭 요청, 멘토링 기록, 기금 등)은 `mission_status = 'approved'`일 때만 허용. 나중에 안정되면 enum 값을 `member`로 정리.

**챕터와 업종 독점**
- `chapters`(기존 `텐트`) 확장: `capacity_min`(개설 최소), `capacity_max = 50`, `status = forming | active | full`.
- `industry_categories(id, name_ko, name_en, parent_id)` — **표준 업종 목록**. 지금 `mentor_profiles.industry`는 자유 입력이라 독점 판정이 불가능하므로 이 표로 바꾼다.
- `mentor_profiles.category_id` 추가. **부분 유일 인덱스** `unique (chapter_id, category_id) where status='active'` 로 DB가 직접 독점을 보장.
- `category_waitlist(chapter_id, category_id, member_id, created_at)` — 업종이 차 있을 때 대기.
- 세부 전문 분야(예: 법률 안의 세무)는 `parent_id`로 나눠 "같은 업종" 범위를 운영진이 조정.

**CBC 활동**
- `meetings`(= 기존 `events`에 `chapter_id` 있음) + `attendance`(기존) : 정기 모임·출석, 대리 참석(`proxy_member_id`) 선택.
- `visitors(id, chapter_id, invited_by, name, contact, category_id, meeting_id, status, follow_up_note)` — 방문자 초대·참관 후 후속.
- `one_to_ones(id, member_a, member_b, held_at, note)` — 1:1 미팅 기록과 챕터 내 "누구와 만났나" 현황.
- `referrals`(기존) — 내부/외부, 진행 상태 유지. `thanks_letters`(기존)는 감사 슬립 역할로 재활용(금액 입력은 선택 사항, 6장).

## 4. 챕터 배정 규칙 (기존 자동 배정 변경)
기존: 시·도/나라별 텐트 자동 배정, 사업가 12명 초과 시 시·군·구로 분할(0011).
변경:
1. 가입 신청 시 **지역과 업종(표준 목록)** 선택.
2. 해당 지역 챕터 중 **그 업종이 비어 있고 50명 미만인 챕터**에 배정 제안. 없으면 같은 지역에 **새 챕터 개설(forming)** 또는 **대기 목록**.
3. 챕터는 개설 최소 인원(제안: 15명, 6장)을 넘으면 `active`.
4. 운영진·리더가 수동 이동 가능(업종 충돌 시 DB가 거부).
5. 기존 `assign_member_tent` 트리거와 12명 분할 함수는 폐기하고 위 규칙의 RPC(`request_chapter`, `approve_member`)로 교체.
6. 용어: 챕터 이름은 현재 "텐트"를 그대로 쓸지 6장에서 결정.

## 5. 선교 권한 흐름
1. 회원이 앱에서 **"선교에 함께하기" 신청**(짧은 동기 입력) → `mission_requests` 생성.
2. **챕터 리더**(자기 챕터) 또는 운영진이 승인/반려. 리더·운영진은 신청 없이 **직접 지정**도 가능(사유 기록).
3. 승인되면 `mission_status = approved`, 앱에 WMTO 메뉴가 열림. 철회(`revoked`)도 가능, 이력은 보존.
4. DB 정책: WMTO 표(`matchings`, `mentoring_logs`, `matching_requests`, 기금 RPC 등)의 접근 조건에 `mission_status = 'approved'` 추가. 앱 화면과 DB 양쪽에서 막는다.
5. 알림: 신청 시 리더·운영진에게, 결정 시 신청자에게(이메일).

## 6. 아직 정할 것
1. **용어**: CBC 모임 그룹을 "챕터"로 할지, 이미 정한 "텐트"를 계속 쓸지(권장: 계속 "텐트" — 이미 정했고 BNI 용어와 구별됨).
2. **개설 최소 인원**: 제안 15명(30~50은 운영 목표, 개설은 더 작게 시작).
3. **활동 지표**: 회원별 월간 리퍼럴·1:1·방문자·출석을 **본인과 리더에게만** 보일지, 챕터 공개 순위를 둘지(권장: 순위 없이 본인·리더 리포트).
4. **감사 슬립 금액 입력**: 사업 성과 금액을 기록할지(권장: 선택, 비공개).
5. **회비**: CBC 회비 유무와 결제 방식(있으면 8장 법인 구조 영향).
6. **업종 표준 목록**: 초안 100여 개를 제안 → 운영진 검토.
7. **영어 서비스 범위**: CBC도 한·영 모두인지.

## 7. 법적 안전 체크리스트 (변호사 확인 필요)
- **상표·명칭**
  - "BNI", "Givers Gain", 로고, 교육 자료, 문서 양식, 용어 모음(TYFCB 등)을 **복사·인용하지 않는다**. 앱 안의 "BNI식 소개" 문구는 제거(남은 위치: `messages/ko.ts`·`en.ts`의 referral/hints, `docs/04`).
  - **"CBC"는 흔한 약어**이고 같은 이름의 기관·상표가 있을 수 있다. 확정 전에 **KIPRIS(한국)·WIPO·USPTO 검색**과 변리사 상담으로 사용 가능 여부 확인, 가능하면 상표 출원.
  - 규칙과 운영 방식(업종 독점, 정기 모임)은 아이디어라 자유롭게 쓸 수 있지만, 문구·디자인은 독자적으로 만든다.
- **개인정보(개인정보 보호법)**
  - 가입 시 수집 항목·목적·보유기간 고지와 동의, 처리방침 갱신(CBC 수집 항목 추가: 업종, 회사, 사진 등).
  - **종교 관련 정보(교회명 등)는 민감정보**로 볼 수 있어 **별도 동의** 필요.
  - **국외 이전**: 데이터베이스가 미국(오리건)에 있다 → 처리방침에 국외 이전 고지, 또는 **서울 리전으로 이전**(권장, 지연 개선과 함께).
  - 회원끼리 연락처·사진 공개 범위를 회원이 정하게 하고, 회원 탈퇴 시 삭제 절차를 둔다.
- **소개·금전**
  - 리퍼럴에 **대가(수수료)** 가 붙거나, 회원 모집 실적에 보상하는 구조는 **다단계·방문판매·유사수신** 소지가 있어 **하지 않는다**. 회비는 서비스 대가로만.
  - 후원금·기부금 영수증은 **지정기부금 단체** 요건이 필요. WMTO(선교) 후원금은 선교 단체 계좌로, CBC 회비와 **계좌·회계를 분리**.
- **조직 형태**: 비영리 사단법인/비영리 임의단체/주식회사 중 무엇이 적합한지, CBC와 WMTO를 같은 단체로 할지는 법무·세무 상담 후 결정(8장).
- **약관**: 이용약관, 커뮤니티 규칙(비방·영업 스팸 금지, 종교 강요 금지), 책임 한계 고지.

## 8. 조직·도메인 구조 선택지 (#5)
| 안 | 내용 | 장점 | 단점 |
|---|---|---|---|
| **A. 한 도메인, 경로로 분리 (권장 시작)** | `/` = CBC, `/wmto` = 선교 사이트, 앱은 `/connect` 하나 | 구현 가장 빠름, 코드·DB 하나, 관리 쉬움 | 브랜드가 한 주소에 섞여 보임, 법인이 다르면 구분이 약함 |
| **B. 도메인 두 개, 같은 앱** | `cbc…` 와 `wmto…`가 같은 배포를 가리키고 호스트에 따라 다른 사이트를 보여 줌 | 브랜드·법인 분리가 선명, 나중에 분리 쉬움 | 호스트별 라우팅·쿠키·이메일 발신 설정이 추가됨 |
| **C. 완전 분리 두 앱** | 서로 다른 저장소·배포 | 완전 독립 | 중복 유지·동기화 비용 큼 (비권장) |
- 권장: **A로 시작하되 B로 갈 수 있게** 호스트 기반 라우팅을 염두에 두고 경로를 설계한다.
- 정해야 할 것: CBC와 WMTO가 **같은 법인/단체인지**, **도메인 이름**, **발신 이메일 주소**, 회비 수납 주체.

## 9. 단계별 작업 (제안)
**0단계 – 결정 확정**: 6장 질문 답, 법률 자문 요청(7장), 상표 검색.
**1단계 – CBC 핵심 (큰 작업)**
  - `industry_categories`, 챕터 독점·정원 규칙, 대기 목록, 배정 RPC (마이그레이션 0014~)
  - 방문자 초대, 1:1 미팅, 정기 모임·출석 화면
  - 앱 이름·문구를 CBC로, "BNI식" 표현 제거, 가입 신청서에 업종·지역 선택
**2단계 – 선교 권한**: `mission_requests`, 리더·운영진 승인 화면, WMTO 메뉴 게이트(DB 정책 포함), 알림 이메일.
**3단계 – 사이트 개편**: CBC 홈페이지 신설, 기존 WMTO 사이트를 `/wmto`로 이동, 리디렉션, 영어판.
**4단계 – 이전·운영**: 서울 리전으로 DB 이전(SVM과 분리), 체험 모드 종료와 정리, 실제 회원 첫 챕터 개설.

## 10. 기존 구현과의 관계 (재사용/교체)
| 항목 | 처리 |
|---|---|
| 회원·로그인·관리자·증명사진·사업가 찾기 | 재사용 |
| 텐트(`chapters`), 정기 모임, 공지·후기 | 재사용·확장(챕터) |
| 지역 자동 배정 + 12명 분할(0011) | **교체**(4장) |
| 리퍼럴·감사 편지 | 재사용(감사는 슬립 역할 추가) |
| 선교사 모시기·멘토링·리포트·순환 기금·후원 | 재사용, **권한 게이트 추가** |
| 체험 모드·가상 데이터 | 곧 종료 예정. CBC 시연이 필요하면 새 가상 데이터로 재작성 |

## 부록. 공개 주소 구조 (구현됨)
- `/`, `/en` = CBC 첫 화면(서비스 이름은 `lib/brand.ts` 한 곳, 가칭).
- `/wmto`, `/wmto/en` = 선교 사역(WMTO) 소개 사이트. 예전 주소(`/about`, `/en/about`, `/apply` …)는 308 로 `/wmto/...` 에 안내.
- `/connect`, `/admin`, `/auth` = 회원 앱(공유). 이후 도메인을 나누려면 `proxy.ts` 의 호스트별 분기와 `localizeHref`(lib/i18n.ts)만 바꾸면 됩니다.
- 남은 정리: 회원 앱 이름 표기("WMTO Connect")·PWA 이름, 개인정보처리방침의 CBC 수집 항목, 상표(KIPRIS) 확인 후 이름 확정.
