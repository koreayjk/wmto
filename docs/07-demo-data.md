# 데모 데이터 (시연용 가상 회원과 활동)

아직 회원도 콘텐츠도 없을 때, 앱이 **활발하게 돌아가는 모습**을 보여 주기 위한 가상 데이터입니다.
실제 운영을 시작하기 전에 SQL 한 번으로 모두 지울 수 있습니다.

| 파일 | 하는 일 |
|---|---|
| `apps/web/supabase/demo/seed_demo.sql` | 가상 데이터 넣기 (한 번만 실행) |
| `apps/web/supabase/demo/view_as.sql` | 시험 계정의 역할을 바꿔 선교사·후원자 화면도 확인하기 |
| `apps/web/supabase/demo/clear_demo.sql` | 가상 데이터 모두 지우기 (실제 데이터는 그대로) |

## 넣는 방법
1. Supabase **SQL Editor → New query**를 엽니다.
2. `seed_demo.sql` 전체를 복사해 붙여 넣고 **Run** 합니다. 마지막에 개수 요약표(mentors 50, partners 20 등)가 나오면 성공입니다.
3. 이미 데모가 들어 있으면 "데모 데이터가 이미 있습니다" 오류가 나며 아무것도 바꾸지 않습니다. (두 번 실행해도 안전합니다.)

> 로그인할 수 있는 **실제 회원(승인된 사업가·선교사)이 있으면 그분의 화면도 함께 채워집니다.** 예를 들어 지금 만든 시험 계정으로 `/connect`에 들어가면 담당 선교사, 멘토링 기록, 리퍼럴, 감사 편지, 대기 중인 매칭 요청이 보입니다.

## 어떻게 구분되나 (그래서 안전하게 지워집니다)
- 데모 회원의 이메일은 모두 `@demo.wmto.invalid` 입니다. 실제 메일 주소가 아니고 **로그인할 수 없습니다.**
- 데모 일정, 스토리, 영상, 챕터의 제목은 `[데모]` 로 시작합니다.
- 실제 선교사 화면을 채우려고 넣는 자립 리포트의 내용도 `[데모]` 로 시작합니다.

## 어디서 보나
- **관리자(`/admin`)**: 신청 목록, 회원(데모 회원 전체), 매칭, 성장 단계(승급 제안), 일정, 스토리, 아카데미에 가상 데이터가 가득 보입니다. 가장 많이 볼 수 있는 화면입니다.
- **회원 앱(`/connect`)**: 로그인한 실제 계정의 역할에 맞춰 보입니다. 사업가 계정이면 담당 선교사와 리퍼럴, 선교사 계정이면 담당 멘토와 자립 리포트가 보입니다. 후원자 화면은 데모로 채워지지 않습니다.
- **공개 홈페이지**: `/stories`(스토리 4개)와 `/events`(다가오는 모임)에 데모가 나타납니다.
- **사업가 / 선교사 / 후원자 화면을 번갈아 보기:** 아래 "역할 바꿔 보기"를 보세요.

## 역할 바꿔 보기 (`view_as.sql`)
데모 회원은 로그인할 수 없으니, **내 시험 계정의 역할을 바꿔서** 선교사나 후원자 화면을 확인합니다.
1. `apps/web/supabase/demo/view_as.sql` 을 엽니다. (먼저 `seed_demo.sql` 을 실행해 두어야 합니다.)
2. 맨 위의 두 줄만 고칩니다.
   - `v_email`: 시험 계정 이메일 (기본값은 `imamerica2414@gmail.com`)
   - `v_role`: `'mentor'`(사업가) / `'partner'`(선교사) / `'sponsor'`(후원자)
3. 전체를 SQL Editor에서 Run 하고, 앱(`/connect`)에서 **새로고침**합니다. 몇 번이고 다시 실행해서 역할을 바꿀 수 있습니다.

| 역할 | 보이는 것 |
|---|---|
| 선교사 | 담당 멘토 2명, 멘토링 기록 8건(다음에 할 것·기도제목), 자립 리포트 5개월, 보낸 감사 편지, 대기 중인 매칭 요청, 성장 단계 Launch |
| 사업가 | 담당 선교사 3명, 멘토링 기록, 받은 리퍼럴 5건과 보낸 리퍼럴 3건, 안 읽은 감사 편지, 수락할 수 있는 매칭 요청 |
| 후원자 | 올해·누적 후원, 후원 중인 선교사, **선교사 소식**(성장 단계, 자립도, 기도제목), **후원 내역**(정기·1:1·캠프·순환 기금), **순환 기금 흐름**(빌려드린 기금, 갚은 기금, 다시 흘러간 기금) |

- 역할을 바꾸면 이전 역할로 붙었던 데모 활동은 정리되고, 새 역할에 맞는 활동이 채워집니다.
- **시연이 끝나면 역할을 원래대로 돌려 두세요.** (`v_role` 을 원래 역할로 두고 다시 Run → `clear_demo.sql`)

## 관리자가 후원 내역을 입력하는 곳
- **관리자 → 후원·기금** (`/admin/donations`)에서 후원 내역과 순환 기금 대여·상환을 직접 입력합니다.
- 입력한 내용은 후원자 앱의 "후원 내역", "선교사 소식", "순환 기금 흐름"에 바로 반영됩니다.
- 후원자(활성 회원)를 먼저 `/admin/members`에서 승인해 두어야 목록에 나타납니다.

## 지우는 방법 (운영 시작 전)
1. SQL Editor에서 `clear_demo.sql` 전체를 실행합니다.
2. 마지막 결과에서 `demo_members_left`, `demo_events_left` 가 모두 **0** 이면 끝입니다.
3. 실제 회원, 실제 신청서, 직접 올린 일정과 스토리는 지워지지 않습니다.

주의
- 데모를 넣은 뒤 **실제 회원이 가입하기 시작하면** 그 회원의 화면에도 데모 활동이 섞여 보일 수 있으니, 실제 운영 전에는 반드시 지우세요. (실제 회원 입장에서는 정리하는 순간 사라집니다.)
- 시연용으로 로그인 가능한 사업가의 "기여 방식"이 비어 있으면 `기술 전수, 경영 코칭`으로 채워 넣습니다. 이 값은 지우기로 되돌아가지 않으니, 내 정보에서 직접 고쳐 주세요.
- SQL을 넣고 나서 일정의 "다가오는 모임" 날짜는 **실행한 날 기준**으로 정해집니다. 오래 두면 지난 모임이 늘어납니다.
