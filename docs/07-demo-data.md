# 데모 데이터 (시연용 가상 회원과 활동)

아직 회원도 콘텐츠도 없을 때, 앱이 **활발하게 돌아가는 모습**을 보여 주기 위한 가상 데이터입니다.
실제 운영을 시작하기 전에 SQL 한 번으로 모두 지울 수 있습니다.

| 파일 | 하는 일 |
|---|---|
| `apps/web/supabase/demo/seed_demo.sql` | 가상 데이터 넣기 (한 번만 실행) |
| `apps/web/supabase/demo/view_as.sql` | 시험 계정의 역할을 바꿔 선교사·후원자 화면도 확인하기 |
| `apps/web/supabase/demo/clear_demo.sql` | 가상 데이터 모두 지우기 (실제 데이터는 그대로) |

## 넣는 방법
1. Supabase **SQL Editor → New query**를 엽니다.
2. `seed_demo.sql` 전체를 복사해 붙여 넣고 **Run** 합니다. 마지막에 개수 요약표(mentors 50, partners 20 등)가 나오면 성공입니다.
3. 이미 데모가 들어 있으면 "데모 데이터가 이미 있습니다" 오류가 나며 아무것도 바꾸지 않습니다. (두 번 실행해도 안전합니다.)

> 로그인할 수 있는 **실제 회원(승인된 사업가·선교사)이 있으면 그분의 화면도 함께 채워집니다.** 예를 들어 지금 만든 시험 계정으로 `/connect`에 들어가면 담당 선교사, 멘토링 기록, 리퍼럴, 감사 편지, 대기 중인 매칭 요청이 보입니다.

## 어떻게 구분되나 (그래서 안전하게 지워집니다)
- 데모 회원의 이메일은 모두 `@demo.wmto.invalid` 입니다. 실제 메일 주소가 아니고 **로그인할 수 없습니다.**
- 데모 일정, 스토리, 영상, 챕터의 제목은 `[데모]` 로 시작합니다.
- 실제 선교사 화면을 채우려고 넣는 자립 리포트의 내용도 `[데모]` 로 시작합니다.

## 어디서 보나
- **관리자(`/admin`)**: 신청 목록, 회원(데모 회원 전체), 매칭, 성장 단계(승급 제안), 일정, 스토리, 아카데미에 가상 데이터가 가득 보입니다. 가장 많이 볼 수 있는 화면입니다.
- **회원 앱(`/connect`)**: 로그인한 실제 계정의 역할에 맞춰 보입니다. 사업가 계정이면 담당 선교사와 리퍼럴, 선교사 계정이면 담당 멘토와 자립 리포트가 보입니다. 후원자 화면은 데모로 채워지지 않습니다.
- **공개 홈페이지**: `/stories`(스토리 4개)와 `/events`(다가오는 모임)에 데모가 나타납니다.
- **사업가 / 선교사 / 후원자 화면을 번갈아 보기:** 아래 "역할 바꿔 보기"를 보세요.

## 역할 바꿔 보기 (`view_as.sql`)
데모 회원은 로그인할 수 없으니, **내 시험 계정의 역할을 바꿔서** 선교사나 후원자 화면을 확인합니다.
1. `apps/web/supabase/demo/view_as.sql` 을 엽니다. (먼저 `seed_demo.sql` 을 실행해 두어야 합니다.)
2. 맨 위의 두 줄만 고칩니다.
   - `v_email`: 시험 계정 이메일 (기본값은 `imamerica2414@gmail.com`)
   - `v_role`: `'mentor'`(사업가) / `'partner'`(선교사) / `'sponsor'`(후원자)
3. 전체를 SQL Editor에서 Run 하고, 앱(`/connect`)에서 **새로고침**합니다. 몇 번이고 다시 실행해서 역할을 바꿀 수 있습니다.

| 역할 | 보이는 것 |
|---|---|
| 선교사 | 담당 멘토 2명, 멘토링 기록 8건(다음에 할 것·기도제목), 자립 리포트 5개월, 보낸 감사 편지, 대기 중인 매칭 요청, 성장 단계 Launch |
| 사업가 | 담당 선교사 3명, 멘토링 기록, 받은 리퍼럴 5건과 보낸 리퍼럴 3건, 안 읽은 감사 편지, 수락할 수 있는 매칭 요청 |
| 후원자 | 올해·누적 후원, 후원 중인 선교사, **선교사 소식**(성장 단계, 자립도, 기도제목), **후원 내역**(정기·1:1·캠프·순환 기금), **순환 기금 흐름**(빌려드린 기금, 갚은 기금, 다시 흘러간 기금) |

- 역할을 바꾸면 이전 역할로 붙었던 데모 활동은 정리되고, 새 역할에 맞는 활동이 채워집니다.
- **시연이 끝나면 역할을 원래대로 돌려 두세요.** (`v_role` 을 원래 역할로 두고 다시 Run → `clear_demo.sql`)

## 공개 데모 체험 (누구나 들어와서 보기)
- 공유 주소: **`https://wmto.vercel.app/connect/demo`** 의 "체험 시작하기" 버튼 한 번으로 들어갑니다. 비밀번호도 가입도 필요 없습니다.
- 안에서 위쪽 검은 막대의 **사업가 / 선교사 / 후원자**를 눌러 모드를 바꿔 볼 수 있습니다. 모드마다 활동이 가장 풍부한 가상 회원의 화면이 나옵니다.
- **읽기 전용**입니다. 저장, 수정, 삭제가 막혀 있고(앱과 데이터베이스 양쪽에서), **가상 회원(@demo.wmto.invalid)의 데이터만** 볼 수 있습니다. 실제 회원 데이터는 볼 수 없습니다.
- 준비물: `0006`, `0007` SQL 실행 + `seed_demo.sql` 로 데모 데이터 넣기. (데모 데이터가 없으면 "아직 준비되지 않았습니다"가 나옵니다.)
- 데모 계정은 첫 입장 때 자동으로 만들어집니다(이메일 `wmto-demo@example.com`, 메일은 발송되지 않음). 바꾸려면 Vercel 환경 변수 `DEMO_ACCOUNT_EMAIL` 을 설정하세요.
- 끄고 싶으면 Supabase **Authentication → Users**에서 이 데모 사용자를 삭제하세요. 입장하는 순간 다시 만들어지므로, 완전히 막으려면 `clear_demo.sql` 로 데모 데이터를 지우세요. (데모 데이터가 없으면 입장이 되지 않습니다.)

## 관리자가 모든 회원의 앱 화면 보기
- **관리자 → 앱 화면 보기** (`/admin/view-as`): 지금 돌아가고 있는 활동(최근 멘토링, 리퍼럴, 감사 편지, 매칭, 후원)과 회원 목록이 나옵니다.
- 회원 옆의 **앱 화면 보기**를 누르면 그 회원의 시점으로 회원 앱이 열립니다. 위쪽 검은 막대의 **나가기**로 돌아옵니다. 읽기 전용이라 아무것도 저장되지 않습니다.

## 관리자가 후원 내역을 입력하는 곳
- **관리자 → 후원·기금** (`/admin/donations`)에서 후원 내역과 순환 기금 대여·상환을 직접 입력합니다.
- 입력한 내용은 후원자 앱의 "후원 내역", "선교사 소식", "순환 기금 흐름"에 바로 반영됩니다.
- 후원자(활성 회원)를 먼저 `/admin/members`에서 승인해 두어야 목록에 나타납니다.

## 지우는 방법 (운영 시작 전)
1. SQL Editor에서 `clear_demo.sql` 전체를 실행합니다.
2. 마지막 결과에서 `demo_members_left`, `demo_events_left` 가 모두 **0** 이면 끝입니다.
3. 실제 회원, 실제 신청서, 직접 올린 일정과 스토리는 지워지지 않습니다.

주의
- 데모를 넣은 뒤 **실제 회원이 가입하기 시작하면** 그 회원의 화면에도 데모 활동이 섞여 보일 수 있으니, 실제 운영 전에는 반드시 지우세요. (실제 회원 입장에서는 정리하는 순간 사라집니다.)
- 시연용으로 로그인 가능한 사업가의 "기여 방식"이 비어 있으면 `기술 전수, 경영 코칭`으로 채워 넣습니다. 이 값은 지우기로 되돌아가지 않으니, 내 정보에서 직접 고쳐 주세요.
- SQL을 넣고 나서 일정의 "다가오는 모임" 날짜는 **실행한 날 기준**으로 정해집니다. 오래 두면 지난 모임이 늘어납니다.

## 체험 모드(/connect/demo)를 풍부하게 보여 주기

- `seed_demo.sql` 에 대표 회원(`demo.showcase.mentor/partner/sponsor@demo.wmto.invalid` — 김은혜·이소망·최은성)이 들어 있습니다. 체험 모드는 모드마다 이 회원으로 먼저 열립니다.
- 소개 화면에 "WMTO가 무엇인지 · 6단계 흐름 · 세 역할"이 나오고, 홈 맨 위에 역할별 "이렇게 둘러보세요" 카드가, 각 화면 위에는 그 화면이 하는 일 안내가 나옵니다.
- 체험 모드에서 저장 버튼을 누르면 오류 대신 "저장되지 않아요" 안내가 뜹니다(언어 변경·로그아웃 제외).
- 반영하려면 Supabase SQL Editor에서 `clear_demo.sql` → `seed_demo.sql` 순서로 다시 실행하세요.

## 텐트 모임 (0009)

- "텐트"는 지역(또는 온라인) 모임입니다(DB 테이블은 기존 `chapters`). 사업가·후원자는 자기 텐트(`members.chapter_id`)에 속하고, **선교사는 따로 신청하지 않습니다.** 텐트의 사업가 한 명이 "우리 텐트로 모시기"(1단계)를 하면 선교사가 그 텐트의 구성원이 되고, 텐트원 중 멘토가 되고 싶은 사람이 "멘토로 함께하기"(2단계)로 직접 맡습니다. 텐트에 모셨다고 모든 텐트원이 멘토가 되지는 않으며, 텐트에 속한 선교사는 그 텐트의 사업가만 맡을 수 있습니다(`0010`).
- 앱 `/connect/tent`: 구성원, 다음·지난 모임(출석 수), 공지·모임 후기(사업가가 작성), 그리고 사업가에게는 "텐트로 모실 선교사"(1단계)와 "멘토를 기다리는 선교사"(2단계) 목록.
- 관리자 `/admin/tents`: 텐트 만들기, 사업가·후원자 배정. `/admin/events` 에서 모임을 특정 텐트에 묶을 수 있습니다.
- 데모 데이터를 다시 반영하려면 `0009`, `0010` 실행 후 `clear_demo.sql` → `seed_demo.sql`.

## 지역별 텐트 자동 배정 (0011)

- 텐트는 **지역별로 자동** 만들어집니다. 한국은 서울·경기도·충청남도·충청북도·강원도·전라남도·전라북도·경상남도·경상북도·제주도, 광역시(부산·대구·인천·광주·대전·울산)와 세종은 따로, 다른 나라는 나라별로 한 텐트입니다.
- 사업가·후원자가 지역 정보(`country`, `region`, `district`)를 가진 채 활성 회원이 되면(승인, 또는 프로필에서 지역 수정) 자동으로 그 지역 텐트에 들어갑니다. 지역을 바꾸면 새 텐트로 옮겨집니다. 선교사는 지역과 무관하게 "텐트에 모시기"로만 들어옵니다.
- 한 텐트의 **사업가가 12명을 넘으면** 같은 텐트 안에서 시·군·구(해외는 도시)를 기준으로 인원이 비슷하게 둘로 나뉘고 이름이 `서울 1텐트`, `서울 2텐트`처럼 바뀝니다(더 늘면 계속 나뉨). 한 시·군·구에만 몰려 있으면 나눌 수 없어 그대로 둡니다.
- 데모 회원은 실제 회원과 텐트가 섞이지 않도록 별도 텐트(`[데모] …`)에 들어가고, `clear_demo.sql` 이 함께 지웁니다.
- 지역 정보가 없는 회원은 `/admin/tents` 에서 직접 배정하거나 "지역 정보로 자동 배정" 버튼을 누릅니다.
- 반영: `0011` 실행 후 `clear_demo.sql` → `seed_demo.sql`.

※ 활발함을 보여 주려고 최근 며칠 안의 멘토링 기록·리퍼럴·후원·오늘 저녁 모임까지 넣었습니다. 사업가 이메일은 `demo.mentor001` 처럼 3자리 번호입니다.

## 증명사진·멘토링 공유 (0013)
